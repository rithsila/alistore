# TEST-10 — Accessibility Checklist

> **Task:** TEST-10 (`ImplementPlan.md`) — _Accessibility_
> **Objective:** Verify a11y basics.
> **Requirements:** ≥44px touch targets, contrast on coral/ink, Khmer rendering, labeled inputs.
> **Acceptance criteria:** Targets ≥44px; no contrast failures; Khmer legible.
> **Dependencies:** FRONTEND-02 (fonts), FRONTEND-03 (button + pill primitives).

This is a **manual a11y checklist** with a **static-verification** layer. Two
kinds of rows:

- **▣ Static (verified from source):** sizes, labels, roles, and the contrast
  math are fixed in the component code and can be confirmed by reading it — these
  are pre-checked here with the file/line evidence, since they cannot drift
  without a code change. The token contrast ratios are computed from the exact
  hex values in `tailwind.config.js` (WCAG 2.x relative-luminance formula).
- **☐ Runtime (pending):** anything that needs a real render, a pointer/touch
  device, a screen reader, or an automated axe pass — left unchecked for a
  manual/UAT run. These have **not** been executed from this environment (no
  browser/AT session was run for this task; the existing Playwright specs assert
  behavior, not a11y).

Targeted level: **WCAG 2.1 AA** for contrast (the acceptance bar), with the
**AAA 44×44 touch-target** floor that `DESIGN.md §"Touch Targets"` already
commits the system to. Mark each runtime row **✓ Pass / ✗ Fail / — N/A** with a
note. Any ✗ blocks the acceptance criteria.

> **Khmer note (locked):** v1 is **English-only** (CLARIFY-02 locked;
> `design.md` forbids Khmer fonts / `lang="km"` until v2; `src/lib/fonts.ts`
> ships a Latin-only subset and `app/layout.tsx` sets `<html lang="en">`). There
> is therefore **no Khmer text or font in v1** to render, so the "Khmer
> rendering / legible" requirement is **N/A for v1** and recorded as a v2
> activation row (Track D). This is the rule-driven resolution of the task
> wording vs. the locked English-first decision — not added Khmer support.

## Track A — Touch targets (≥44px)

The implemented sizes above are fixed in code (▣). Runtime rows confirm the
rendered/tappable reality on a device.

- [▣] All primary controls render at ≥44px (table above; smallest is `h-11` = 44px exactly, used for chips, icon buttons, steppers, swatches).
- [☐] On a real touch device (360px), every control in the PLP → PDP → cart → checkout → KHQR flow is tappable without mis-hits; adjacent steppers (− / +) and adjacent chips do not overlap their hit areas (they sit in `gap-2` = 8px rows).
- [☐] The PDP color swatch's 44×44 **hit area** (not just the 32px visible dot) is tappable to its edges.
- [☐] Disabled controls (empty-bag Checkout, sold-out size pills, busy steppers) are visibly disabled (`opacity` 40–50%) and not actionable.
- [☐] Desktop inline links (Note N1) are comfortably clickable with a mouse; no reliance on them as the *only* touch path on mobile (mobile uses the hamburger drawer's `py-3` links instead).

- [▣] **`accent` (coral) text** on `canvas` = 5.08:1 and on `soft-cloud` = 4.66:1 — clears AA. Coral appears in exactly its two sanctioned uses: **sale price** (`BuyBox`, `ProductCard`, `cart/page` `UnitPrice`) and **"Pay with KHQR"** outline CTA label (`BuyBox` `KHQR_BUTTON`).
- [▣] **`PillButton`** = `canvas` on `ink` = 18.9:1 (white label on ink fill).

- [▣] **`success`** text = 5.22:1 on canvas.
- [☐] Visually confirm coral does **not** appear anywhere except sale price + KHQR CTA (design rule; e.g. "Sale" nav item and payment radios are intentionally `ink`, not accent — verified in source: `TopNav` and `checkout/page` comments).
- [☐] Run an automated checker (axe-core / Lighthouse / WAVE) on `/`, `/category/[handle]`, `/product/[handle]`, `/cart`, `/checkout`, `/checkout/khqr`, `/order/[id]` — **zero** contrast violations expected for text.
- [☐] Focus indicator is visible on every control: fields flip to a **2px `ink` border** on `focus` (`ink` on soft-cloud/canvas ≥17:1) — confirm it's perceivable and not clipped (N3).

## Track C — Labeled inputs, form & landmark semantics, keyboard

- [▣] **Every checkout field has an explicit `<label htmlFor>` ↔ `id` pair:** `delivery-full-name`, `delivery-phone`, `delivery-email`, `delivery-address`, `delivery-note` (`DeliveryForm`). Phone carries `required` + `aria-required` + `aria-invalid` + `aria-describedby="delivery-phone-help"`; email has `aria-describedby="delivery-email-help"`.
- [▣] **Correct input semantics:** `type="tel"` + `inputMode="tel"` + `autoComplete="tel"` (phone), `type="email"` + `autoComplete="email"` (email), `autoComplete="name"` / `"street-address"` (name / address) — mobile keyboards + autofill resolve correctly.
- [▣] **Payment choice is a labeled radio group:** `<fieldset>` + `<legend>Payment</legend>`; each option is a `<label>` wrapping a real `<input type="radio" name="payment-method">` (the visible dot is `aria-hidden`, the input is `sr-only` but focusable) — selectable by keyboard and announced (`app/checkout/page` `PaymentChoice`).
- [▣] **Search input** (`SearchPill`) is `type="search"` and forwards `aria-*`/`placeholder` props; when mounted, the caller must pass an `aria-label`/associated label (no visible label in the pill by design). → confirm at each mount site (N4).
- [▣] **Icon-only controls are named:** nav `aria-label`s ("Open menu", "Search", "Account", "Bag, N items", "Close menu"), cart "Decrease/Increase quantity" + "Remove {name}", filter "Close filters", swatch `aria-label={color}` / `"{size}, sold out"`.
- [▣] **Live regions / grouping:** stock note + qty readout use `aria-live="polite"`; the checkout error uses `role="alert"`; color/size/currency/quantity sets use `role="group"`/`<fieldset>` with `aria-label`/`<legend>`; filter groups use `<fieldset><legend>`.
- [▣] **Landmarks:** `<header><nav aria-label="Primary">`, `<main>`, `<footer>` with per-column `<nav aria-label>`, order summary `aria-label="Order summary"`; one `<h1>` per page (e.g. cart "Bag").
- [☐] **Keyboard walkthrough (runtime):** Tab order is logical; the mobile nav drawer and filter drawer are reachable, operable, and **dismiss with `Esc`**; focus is not lost behind a closed drawer (drawers use `pointer-events-none` when closed — verify focus can't land inside a hidden panel). _(Esc-to-close is not yet wired in `TopNav`/`FilterSidebar`; confirm or log as a follow-up — N5.)_
- [☐] **Screen-reader pass (runtime):** each field's label + helper is announced; the phone error (`aria-invalid` + helper text swap) is announced; radio group reads "Payment, KHQR/COD"; sold-out sizes read as such; bag count changes are announced.
- [☐] Visible focus ring is present and follows the tab through all of the above.

## Notes & known a11y constraints

These are **expected** given the locked design system (`design.md`: flat,
hairline-only, no shadows/gradients, English-only). The checklist passes if the
documented behavior holds.

- **N1 — Inline text links < 44px (desktop nav, wordmark, footer).** Desktop
  category links, the wordmark, and footer links are inline text, not padded
  44px boxes. WCAG **2.5.5 (AAA, 44px)** and **2.5.8 (AA, 24px)** both carve out
  an **inline exception** for links in flowing text, and these are pointer-context
  (≥600px) or footer links — the **mobile** primary actions all use the 44px
  hamburger-drawer links instead. Not a blocker; confirm they're comfortably
  clickable.
- **N2 — `mute` on `soft-cloud` = 4.53:1 (marginal AA).** Clears the 4.5 bar but
  with little headroom; it only applies to **placeholder** text inside fields
  (real entered text is `ink`, 17:1). Acceptable; flagged so a future token tweak
  doesn't quietly drop it below 4.5.
- **N3 — Field affordance relies on a low-contrast fill, covered by focus.** A
  resting field is `bg-soft-cloud` on a `canvas` page (~1.09:1 boundary — below
  the 3:1 UI-component bar in isolation). By design (flat system, no borders at
  rest) the field is still identifiable by its fill + shape + visible `<label>`,
  and the **focus** state adds a **2px `ink` border** (≥17:1) — a strong,
  compliant focus indicator. Verify the focus border is never clipped by the
  pill radius.
- **N4 — `SearchPill` has no built-in visible label.** It's a reusable primitive;
  accessibility depends on the **caller** supplying an `aria-label` (or a
  `<label>`). Audit every mount site when search is wired into a page.
- **N5 — Drawers have no `Esc`-to-close / focus-trap yet.** `TopNav` and
  `FilterSidebar` open/close via button + backdrop and set `pointer-events-none`
  when closed, but do not trap focus or bind `Esc`. Confirm keyboard users can
  still operate and escape them; if not, log a small follow-up (keyboard a11y
  hardening) — it is **not** in TEST-10's Deliverables.
